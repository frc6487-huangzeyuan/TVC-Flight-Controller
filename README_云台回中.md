# TVC 方位＋俯仰云台回中 · 主控与控制台 2.4.3

主控入口为本目录的 `TVC_Electronics.ino`。控制台为上一级目录的 `TVC控制台.html`；单文件已包含 CSS 和 JavaScript，可以独立复制使用。网页源文件在 `web/dist`，运行 `node tools/embed_web.mjs` 会同时生成单文件页面和固件中的 `WebAssets.h`。

本工程实现箭体两向倾斜的 PID 回中和云台映射，并提供按真实倾斜自动增减油门、独立手动调速及三维几何预览。没有高度、下降速度、位置或着陆点控制；MPU6050 本身不能提供完整自动降落所需的信息。两路云台也不能独立控制绕箭体长轴的自旋。

## 硬件与数据流

| 功能 | 主控 GPIO / 配置 |
| --- | --- |
| 360°位置舵机，底部方位旋转 | GPIO4，500～2500µs 暂映射为 0～360° |
| 270°双轴位置舵机，俯仰 | GPIO5，额定映射 0～270°；实际限制 85～185°（中位 ±50°） |
| 已有电调信号 | GPIO6，仍需在页面单独启用和启动 |
| 主控接收 SuperMini | RX16 ← 采集板 TX6 |
| 主控发送给 SuperMini | TX17 → 采集板 RX7 |
| 板间串口 | 460800 baud，原二进制请求/响应协议不变 |
| IMU1，可切换控制来源 | 采集板连接的 MPU6050，I2C 地址 0x68 |
| IMU2，默认控制来源 | 主控 SDA9、SCL10、INT8，AD0 接 3.3V，地址 0x69 |
| 电脑串口 | 460800 baud，JSON＋CRC 遥测，可由看板读取 |

舵机用符合具体型号要求的独立电源，主控、采集板、IMU 和舵机信号地共地。360°舵机已按用户确认的“可指定角度的位置舵机”处理。270°双轴按同轴双输出、一个控制自由度处理。

500～2500µs 是示例规格映射，实际舵机型号和行程尚未实测确认。中位脉宽均为 1500µs，对应方位 180°、俯仰 135°。

主控默认使用本地 IMU2（0x69，200Hz）作为显示和 PID 的唯一当前来源。网页顶部的 IMU1／IMU2 开关同时切换姿态、趋势、当前原始数据和 PID 输入；不是只改网页标签。切换命令由设备确认后才更新页面，目标模块未检测到时拒绝切换并保留原来源。

切换先停止舵机／电机输出并复位 PID，清除上一来源的零偏、姿态和安装参考；姿态模式下会等待新样本，重新进行约 3 秒竖直静止校准。校准通过后仍需手动启动。手动模式切换只清除参考，进入姿态模式时再校准。上电默认 IMU2，切换不写入持久存储，不自动故障接管。

未被选中的通道仍采集供校验，其故障和重启不会触发当前来源的控制故障；已选中通道无新数据时沿用历史计算窗口，超过 2 秒停止输出。`control.source_id` 和 `control_imu` 是设备实际控制源及其状态；`imus[0]` 是远端 IMU1 原始缓存，`imu2` 是本地 IMU2 原始监测。IMU2 监测卡的辅助倾角沿用独立安装矩阵，当前控制姿态使用所选模块重新校准所得的矩阵，不能把两者直接混用。

当前主控与控制台均为 2.4.3，使用协议 10：需要重新上传本目录完整工程并刷新网页。仅刷新页面、或上传独立 CSV 传感器测试程序，无法使用这个切换功能。

当前目录没有 SuperMini 采集固件源码；本次没有修改采集侧接线或固件。主控要求采集板继续使用已有协议，并实际读取 0x68、±4g、±500°/s、200Hz 的 MPU6050 数据。采集侧实际地址、芯片身份和物理接线仍需实物核对；选择 IMU1 时仍严格使用这路远端数据。

## 2.4.3 八边形斜面的安装校准

视频与后补照片对应的布局为：IMU1 在左前斜面，IMU2 在右前对称斜面，中间隔着正面；两块 PCB 仍沿箭体竖直，朝外法线相差 90°。用户确认从箭头向尾部看，IMU1 在 IMU2 的顺时针 90°处。不能把“斜面相对机构轴偏 45°”当作“两块 IMU 彼此相差 45°”。

公共机体坐标采用以下右手约定：

- 机体 +Z：箭头向上；
- 机体 +X：视频画面向右的机构参考方向；用户确认方位 180°、俯仰从 135°增至 145°时喷口向这一侧偏；
- 机体 +Y：+Z × +X。

`bench_config.h` 中 `IMU2_MOUNT_YAW_DEG=-45°`、`IMU1_MOUNT_YAW_DEG=-135°`，表示各 PCB 朝外法线相对公共 +X 的方位；从箭头向尾部俯视，逆时针为正。该正负号由上述机构参考及安装面位置推得，尚未用实物倾斜验证。

校准时仍须箭体长轴竖直、箭头朝上、板面竖直，静止约 3 秒。程序先用真实重力建立当前传感器的局部上下及朝外轴，再按当前来源的安装角旋转到公共坐标。组合矩阵同时作用于加速度与去零偏后的角速度，之后才进行四元数姿态估计与 PID；不是在欧拉角上直接减去 45°。重力无法单独辨识绕箭体长轴的安装偏角，因此重新竖直校准不会自动消除这个方位偏差。

切换来源仍停止输出并重新校准，但分别使用各自安装偏角，转换后 +X/+Y 保持相同含义。看板来源区显示设备回传的 `control.mount_yaw_deg`；故障复制文本也包含安装角和当前矩阵。旧固件未提供此字段时明确提示上传新主控，不把预设值显示为已生效。三维预览默认跟随设备矩阵；手动预览轴映射仍仅影响图形。

这是利用已知竖直参考进行标定，不能从任意静止姿态推断箭头方向。如果斜放箭体进行校准，会把该姿态误当作竖直参考。安装位置改变后需修改对应偏角并重新标定。当前修改保留既有云台方位零位、修正符号、PID 参数、限速、俯仰限位、油门及心跳告警逻辑。

处理方式参考 [PX4 的传感器安装方向说明](https://docs.px4.io/v1.18/en/config/flight_controller_orientation)及 [ArduPilot 的安装旋转定义](https://github.com/ArduPilot/ardupilot/blob/master/libraries/AP_Math/rotations.h)，复用本工程矩阵算法，没有引入飞控库。

姿态用原工程的四元数估计。控制误差取世界竖直向量在机体中的分量，不用处于奇异位置的欧拉航向作为回中依据；箭体竖直时可以正常建立参考。相对航向仍由陀螺仪估计，存在漂移，仅供显示。

## PID 与云台动作

### 电机启动前预定位（姿态模式）

点击“开始姿态回中”后，即使电机尚未启动，主控也会根据实时 IMU 姿态持续更新舵机纠偏指令。姿态模式请求电机启动时，主控再以当前有效控制 IMU 姿态和 PID 比例项计算纠偏向量，选择较近的等效方位和带符号俯仰角。舵机按现有 3µs/10ms 限速移动，电调保持停止脉宽；目标 PWM 发出后额外等待 `PREPOSITION_SETTLE_MS`（当前 2000ms），同时完成电调停止脉宽的启动保持。两者都完成后才允许电机启动并进入姿态控制。准备期间姿态变化超过 2°、姿态失效或超时将停止输出；取消、断开或故障也会中断准备。手动模式的电机测试不使用此预定位。

此等待基于已发送指令，不是舵机位置反馈；即使时间结束，也不能证明机械实际到位、方向正确或电调停止脉宽可靠。应按舵机规格及实际负载测量设置 `PREPOSITION_SETTLE_MS`，并在拆桨条件下核对两轴方向、电调停止与故障停止。先保持箭体竖直静止完成 IMU 校准，再摆到测试初始姿态；倾斜状态下不能重新做竖直校准。

2.2.2 将舵机指令变化上限由每 10ms 的 10µs 降为 3µs（300µs/s），即原上限的 30%。按现有脉宽映射，方位指令上限约 54°/s、俯仰指令上限约 40.5°/s。自动回中和启用后的手动目标移动共用此限速；PID 增益及最大补偿幅度保持不变。这里是 PWM 指令限速，不是舵机实测速度；首次启用时仍直接发送 1500µs 中位指令。

两路 PID 分别处理 X、Y 向倾斜，输出形成二维修正向量，再换算成方位角和俯仰偏转角。没有把两只舵机当作两路互相独立的俯仰/横滚执行器。

使用对测量值的微分、30ms 微分低通、积分限幅、矢量输出限幅，以及每 10ms 最多 3µs 的输出变化限制。输出受限或方位仍在大幅转向时，限制积分继续增大；反方向积分仍可消除已有积累。控制任务独立按 100Hz 计算，真实测量滤波器只在收到新样本时推进。

## 没有新样本时的处理

2.2.0 把原来的“主 IMU 超过 50ms 就立即停机”改为历史计算窗口：

| 最新真实样本年龄 | 行为 | 看板状态 |
| --- | --- | --- |
| 0～50ms | 使用最近姿态和角速度推进到当前控制时刻 | 实时 |
| 50～150ms | 用最近有效角速度外推，等待新样本 | 历史估算 |
| 150ms～2s | 保持外推到 150ms 时的估计姿态，继续计算云台指令 | 历史保持 |
| 达到 2s | 历史窗口结束，停止输出并报告 IMU_TIMEOUT | 历史超时 |

这些值集中在 `bench_config.h` 的 `IMU_FRESH_US`、`HISTORY_PREDICTION_US`、`IMU_TIMEOUT_US`。控制任务本身的最大调度间隔仍是独立的 `PID_MAX_TICK_GAP_US=50000`，它不再与测量过期阈值混用。

历史姿态从最近真实姿态的副本计算，不写回真实样本滤波器；因此下一份新数据到来时，不会把之前预测的时间再重复积分。历史加速度不被反复当成新的重力测量；没有新测量时不继续增加 PID 积分。样本时间戳保持不变，看板显示其真实年龄。

新样本在历史窗口内恢复时，会用历史角速度衔接缺帧时间，再用新测量更新，不因为一次超过 50ms 的采样间隔就丢弃姿态参考。历史预测假设短时间内角速度延续，属于估算；超过 150ms 后不再无限外推。此前从未收到有效样本或未完成姿态校准时，不会凭空生成历史姿态。校准仍要求新采集的真实样本，结束时也检查真实测量是否新鲜；缓存不计作新校准样本。

板间协议的重复帧、旧会话、CRC 及传输中陈旧样本检查保留；历史复用的是已经接收且通过校验的有效样本。未被选中的 IMU 不参与当前姿态计算和 PID。网页遥测连接宽限从 750ms 改为 2500ms，握手仍必须得到真实固件回复；修改历史窗口不能修复首个握手没有回复的问题。

相同偏转向量可用“方位转 180°＋俯仰反向偏转”表示，程序按有限行程内较近的方位指令选择，避免在 0/360°边界突然跨越整圈。偏转接近零时，俯仰回到 135°，方位保持当前指令，因为此时方位没有唯一解。手动页面的“机械回中”会明确发送方位 180°、俯仰 135°。

方位还在大幅转向时，先让俯仰指令靠近中位。这里判断的是已发送指令，不是实际舵机位置反馈，具体跟随速度仍需测试。

默认参数为：两向 Kp=0.6、Ki=0、Kd=0.03；积分贡献限制 ±3°；云台总偏转限制 ±15°。这些是初始试调参数，没有经过实物整定。看板允许在输出停止时调整 PID、最大偏转、方位零位和两向修正符号，并等待设备回传确认。参数只对本次运行有效，重启恢复 `bench_config.h` 默认值。

2.2.1 已取消按箭体倾斜角度超过 60°停止输出的判断。姿态含 NaN/Infinity、当前 IMU 连续 2 秒无有效新样本或发生其他控制故障时，仍会停止输出。取消角度停机条件不代表大角度回中效果已经实物验证。电机运行时沿用原工程逻辑，关闭加速度重力反馈，短时间依靠陀螺仪传播姿态，以免把推力加速度当作重力；这时姿态误差仍可能随时间积累。

## 2.4.0 俯仰限位与自动油门

俯仰中位为 135°，机械限位为 85～185°（相对中位 −50～+50°）。对应脉宽向内取整为 1130～1870µs，网页滑条、固件手动命令、PID 目标与最终 PWM 输出均执行该范围。默认 PID 最大补偿仍为 15°，网页可在机械范围内调整至 50°。

自动油门使用当前控制源的真实姿态，取箭体 +Z 与世界 +Z 的夹角，不使用三维预览轴映射。计算规则是 `基础油门 + max(0, 倾斜角 − 死区) × 增益`，再执行上限及变化速度限制。默认基础值 0%、增益 1%/°、上限 30%、死区 2°、变化速度 10%/秒；例如倾斜 12°时请求 10%油门，竖直时回到基础油门。

百分比代表停止脉宽到正向最大脉宽的比例；当前网页电调配置为停止 1500µs、正向最大 1700µs，所以 30% 对应 1560µs。没有实际 RPM、推力、下降速度或高度反馈，这不是转速闭环或自动着陆控制。参数是台架初试值，未做实物整定。

该功能默认关闭。先停止输出、配置参数并勾选“允许根据真实箭体倾斜自动调节油门”，再点击“开始回中 + 自动油门”。程序先让电调在停止脉宽完成约 3 秒启动准备，确认后才启用姿态 PID 和自动油门。取消勾选或“只停止电机”会停止电机并保留已运行的舵机回中；停止自动控制、切换数据源/模式、故障或断开会同时停止联动输出。历史姿态期间可保持或降低油门，不能在缺少新测量时继续增加；连续 2 秒无有效样本仍停止输出。独立手动调速与自动油门互斥。

## 三维姿态与坐标预览

“设备姿态跟随”直接使用设备姿态矩阵和舵机 PWM 角度指令。“本地姿态模拟”可拖动横滚、俯仰、航向，或手动设置 TVC 方位和俯仰。自动试算仅复用静态 P 分量与云台几何，不模拟 I/D、机械动态、气动力或下降轨迹。图中 W 为世界轴、B 为预览箭体轴、S 为传感器轴；实线为正向、虚线为负向，B+Z 沿箭头。黄色 +T 是推力指令方向，橙色 −T 是喷口排气方向。

轴交换及正负翻转严格只影响预览，不发送硬件命令，不修改真实姿态、安装矩阵、PID 或油门。X/Y/Z 每轴各用一次；左手系组合会标为镜像预览。默认沿用设备安装矩阵，可一键恢复。实现复用本工程的矩阵约定，使用本地 SVG 投影，无 CDN 或外部模型依赖；SVG 响应式布局参考 [MDN viewBox](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/viewBox)。

## 上传和首次台架测试

1. Arduino IDE 打开本目录 `TVC_Electronics.ino`，保留同目录所有 `.ino`、`.h`、`.cpp`。开发板选择 **ESP32S3 Dev Module**，Flash 选 **16MB**，PSRAM 选 **OPI PSRAM**。
2. 构建使用 **esp32 by Espressif Systems 3.3.12**、**ArduinoJson 7.4.3**、**WebSockets 2.7.2**。不需要 ESP32Servo，本工程使用原生 LEDC。保留了 ESP32 core 2.x 的旧输出分支，但本次仅验证 3.3.12。
3. 原生 USB 接口使用 **USB CDC On Boot: Enabled**、**USB Mode: Hardware CDC and JTAG**；如改用 USB 转 UART 接口，需要选择相应的串口配置，本次未验证该路径。
4. 上传新版主控后，使用新版 `TVC控制台.html`，不要混用旧协议页面。推荐 Edge / Chrome；电脑串口监视器和网页不能同时占用同一串口。无线可连接主控热点后访问 `http://192.168.4.1`。
5. 先保持电机停止，在手动页面启用舵机并发送机械中位，确认方位 180°、俯仰 135°确实对应机构中位。舵盘安装偏移应先机械调整。
6. 小幅改变俯仰，确认正向偏转所在平面。方位零位默认 180°；它应对应看板定义的 +X 修正方向。如果不一致，在停止输出后调整“方位零位”，直到机械方向与坐标约定一致。
7. 将箭体竖直、箭头朝上后切换自动页面；需要时点击“竖直静止校准”。确认当前所选 IMU 数据新鲜、采样约 200Hz、两向倾斜接近 0°，再开始姿态回中。
8. 先施加小角度扰动，观察云台指令与实际动作。实际恢复力方向取决于风扇/推进方向、转轴和重心位置，不能仅凭照片确定；若某方向越修正偏差越大，立即停止，核对机械方位，再只翻转相应方向符号。
9. Ki 先保持 0，确认两向方向和机械响应后再调整 P、D；存在稳定偏差时再少量加入 I。查看实时曲线和 P/I/D 贡献，避免用增大参数掩盖坐标或连杆问题。

看板显示的舵机角度、风扇百分比都是指令，不是反馈位置或实测转速。主控上电保持输出关闭，需要你在看板明确启动。

## 查看原始 fault（控制台 2.4.1）

页面顶部新增“原始故障码”区域，持续显示设备遥测的 `fault`，不会被“FAULT_REQUIRES_RESTART”等操作返回码覆盖。连接数据过期和断开后保留的历史快照会明确标注。点击“复制故障信息”可复制故障码、固件、控制源、姿态/PID 与输出状态；浏览器不允许直接写剪贴板时，会提供可选中的文本框。健康遥测恢复时显示“无故障”。

本次只修改网页显示及嵌入网页资源，控制算法和恢复条件不变；本地单文件页面刷新后即可配合 2.4.0 主控使用。设备热点内置页面需要将更新后的网页资源随工程上传才会更新。`PID_INVALID` 是汇总故障码，当前包内故障后的 PID 周期可能已经被复位为 0，不能据此推断最初触发原因。本次网页故障显示、通知覆盖、断开快照、复制/手动复制回退已通过主机检查；未重新编译或上传主控固件。

## 2.4.2 心跳超时仅告警

超过 1 秒没有心跳时，固件只报告 `warning=HEARTBEAT_TIMEOUT` 与 `heartbeat_age_ms`，不再写入硬故障 `fault`，不停止舵机/电机，不重置 PID，也不因该告警拒绝后续控制命令；心跳恢复后自动清除告警。网页以黄色显示并可复制诊断信息，不取消待处理的控制操作。

心跳改为每 200ms 独立发送，单帧 ACK 延迟/丢失不会阻塞后续发送。此前回复等待最多 1800ms，可能长于固件的 1000ms 心跳窗口。本次没有增大窗口，也没有关闭其他故障判断。

改动仅针对心跳监测。主动停止、页面隐藏/关闭时的停止指令、遥测中断后的网页停止指令、USB 会话超过 5 秒无命令后的释放，以及 IMU/PID/姿态/油门等其他故障停机仍保留。需要重新上传 2.4.2 主控并刷新网页；仅更新网页不能改变旧固件已经锁存的 HEARTBEAT_TIMEOUT 硬故障。
